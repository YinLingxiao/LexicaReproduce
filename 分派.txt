Lexica 五人分派（以《任务分派手册》v1.0 为准）
==================================================

一、所有人都要遵守
------------------
1. 环境：Windows x64，MSYS2 UCRT64 的 g++、cmake、ninja，C++17。
   安装：pacman -S mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-cmake mingw-w64-ucrt-x86_64-ninja
2. 编译：双击或运行 build.bat，产物是 build\lexica.exe。
   运行网页版：build\lexica.exe，浏览器打开 http://127.0.0.1:8765
   运行控制台版：build\lexica.exe --cli
   可选参数：--port 端口  --data-dir 数据目录  --web-dir 网页目录
3. 只改自己的目录。要改别人的文件，先找对方或 A。
4. 头文件（.h）里的公开函数是接口合同，A 已经在 src/app/app.cpp 里接好了。
   不要改公开函数的名字、参数、返回值；确实要改，先通知 A 和用到它的人。
   私有成员（private:）和 .cpp 里的内容随便改。
5. 业务代码不要用 cin / cout，返回 ErrorCode 或 Result<T>，由 A 负责显示。
6. 公共定义在 src/common，只有 A 能改：
   types.h   ID 类型和常量（笔记 5000 字、每页 20 条最多 100、建议 8 条、每轮 12 题）
   error.h   错误码
   result.h  Result<T>：成功用 Result<T>::success(值)，失败用 Result<T>::fail(错误码)
   clock.h   时间源，统一用 systemClock().nowUtc()，存 UTC 秒；E 测试时可以换成假时钟
   text.h    normalizeWord：去首尾空白并转小写
7. 时间一律存 UTC 秒（int64），按 Asia/Shanghai 统计日期。
8. 提交流程：
   git pull
   git checkout -b 自己的字母/功能名      例如 c/sqlite
   写代码，build.bat 编译通过
   git push -u origin 分支名
   在 GitHub 上提 Pull Request 给 A，A 合并到 main
9. 每次交给 A 时附上：做了什么、怎么测的、测试数据、已知问题。

二、现在的状态
--------------
整个程序已经能编译运行，所有接口都能调用。
C、D、E 的模块现在是“假实现”：数据存在内存里，重启就没了，规则也是简化的。
每个人的任务就是把自己的假实现换成真的。

三、A 主程序与整合（组长）
--------------------------
负责：CMakeLists.txt  build.bat  src/main.cpp  src/common  src/app  src/api  src/cli  src/ai
已完成：
- 启动流程：找 exe 所在目录 → 检查 data 目录可写 → 打开各模块 → 选择网页或控制台模式 → 退出时关闭
- HTTP 服务：只监听 127.0.0.1，外来网站的写请求返回 403，返回格式统一
- 正式查词编排：C 查词 → 命中后 D 记历史 → E 初始化学习状态
- 复习提交后通知 D 记一次复习
- 控制台菜单，用来早期验证
要做：
- AI：配置保存、连接测试、真实请求、15 秒超时、响应校验（完整词边界）、缓存、异步任务
  密钥只从环境变量 LEXICA_AI_KEY 读，任何接口和日志都不回传密钥
  注意：src/api/server.cpp 里所有 App 调用共用一把锁，等网络时必须先释放这把锁
- 合并大家的 Pull Request，每周打一个能运行的版本
- 写接口说明和异机运行说明

四、B 前端页面
--------------
负责：web 目录（编译时会自动复制到 build\web）
现状：只有 web/index.html，显示服务状态。
要做：五个页面——查词、我的词汇、复习、统计、设置。
      每个页面要有：加载中、空数据、出错、保存中/已保存 这几种状态。
      查词候选支持上下键选择、回车提交、Esc 收起。
      窄屏（480px）到普通桌面宽度都能用。
规则：
- 所有接口返回格式：
  成功 {"ok":true,"data":...}
  失败 {"ok":false,"error":{"code":"错误码","message":"中文说明"}}
  业务错误 HTTP 状态码也是 200，要看 ok 字段；请求格式不对是 400，路径不存在是 404
- 正式查词必须带 op_id（自己生成一个随机字符串）。同一次查词网络重试，用同一个 op_id。
- 输入框打字时调 suggest，不算查词；只有用户提交才调 lookup。
- 分数、复习时间、统计全部以后端返回为准，前端不要自己算。
- AI 密钥不会返回给前端，只显示 key_configured 是否为 true。
- 页面上要区分“尚未导入词库”（DICT_NOT_READY）和“未找到单词”（WORD_NOT_FOUND）。

接口清单：
  GET  /api/status
       → {state, dict_ready}
       state 取值：OK / DICT_EMPTY / DIR_NOT_WRITABLE / DB_CORRUPT / VERSION_TOO_NEW
  GET  /api/suggest?q=前缀
       → [{id, word}]，最多 8 条
  POST /api/lookup  {"word":"apple","op_id":"随机串"}
       → {id, word, phonetic, translation, definition}
  GET  /api/entry/{id}
       → 同上，只读词条，不算查词
  GET  /api/history?page=1&size=20
       → {total, items:[{id, word, utc}]}，最近的在前
  GET  /api/vocab?fav=1&stage=0&paused=0&q=词头&page=1&size=20
       → {total, items:[{id, word, favorite, note, paused, stage}]}
       fav / paused 传 1 或 0，不传表示不筛选；stage 传 0~3，不传表示不筛选
  PUT  /api/vocab/{id}/favorite  {"value":true}
  PUT  /api/vocab/{id}/note      {"text":"笔记，最多 5000 字"}
  PUT  /api/vocab/{id}/paused    {"value":true}
       → {}
  POST /api/review/start
       → {session_id}
  GET  /api/review/{session_id}/next
       → {has:false} 或 {has:true, question:{id, session_id, entry_id, prompt, kind}}
       kind：local 本地释义题 / ai AI 填空题
  POST /api/review/question/{id}/hint    {"level":1}  不传 level 就取下一级
       → {level, text}
  POST /api/review/question/{id}/submit  {"answer":"apple"}
       → {entry_id, correct, duplicate, stage, hint_level}
       duplicate 为 true 表示这题之前提交过，这次没有重复记分
  GET  /api/review/{session_id}/summary
       → {formal_count, formal_correct, practice_count, reinforce:[单词]}
  GET  /api/stats
       → {days:[{date, lookups, reviews}] 共 14 天, stage0, stage1, stage2, stage3, paused}
  POST /api/import  {"path":"本地词库文件路径"}
       → {added, skipped, failed}
  GET  /api/ai/config
       → {enabled, base_url, model, key_configured}
  PUT  /api/ai/config  {"enabled":true,"base_url":"...","model":"..."}
  POST /api/ai/test
  POST /api/ai/example {"id":1,"word":"apple"}
       → {id, status, text}
  GET  /api/ai/task/{id}
       → {id, status, text}，status：pending / running / succeeded / failed
错误码：BAD_REQUEST 参数错误  DICT_NOT_READY 尚未导入词库  WORD_NOT_FOUND 未找到单词
        QUESTION_EXPIRED 题目已失效  DB_ERROR 数据库错误  AI_DISABLED AI 未开启
        AI_KEY_MISSING 未配置密钥  AI_TIMEOUT AI 超时  AI_INVALID AI 响应不合格  FORBIDDEN 来源不被允许

开发方法：先运行 build\lexica.exe，再到设置页调 /api/import（路径随便填）导入假词库，
          里面有 apple、banana、run 三个词，就能把每个页面跑通。

五、C 词库与查词
----------------
负责：src/dict/dict.h  src/dict/dict.cpp，以及公共数据库
现状：假词库在内存里，导入后只有 apple(1)、banana(2)、run(3)。
必须保留的公开函数：
  StartupStatus open(dataDir)            打开或创建数据库，返回启动状态
  void close()
  bool ready()                           词库里有没有词
  Result<Entry> lookup(word)             精确查询
  Result<vector<SuggestItem>> suggest(prefix)   前缀建议，最多 kSuggestMax 条
  Result<Entry> get(id)                  按 ID 读词条
  Result<ImportReport> importFile(path)  导入 ECDICT
返回规则：
  空输入 → BadRequest；词库为空 → DictNotReady；查不到 → WordNotFound
  数据库打不开或坏了 → open 返回 DbCorrupt；版本比程序新 → VersionTooNew
要做：
  1. 引入 SQLite（sqlite3.c / sqlite3.h 放进 third_party，告诉 A 改 CMake）
  2. 数据库文件放在 dataDir 下；做版本号和迁移；所有 SQL 用参数绑定
  3. 导入 ECDICT：先检查表和字段，用事务；同一个词重复导入不能产生两条；
     词条 ID 必须稳定，重新导入不能变；导入失败旧词库还能用
  4. 查询：去空白、统一小写、精确优先；前缀建议排序固定
  5. 词形回退：running 查不到时找原型 run
  6. 查询本身不要写历史（历史由 A 调 D 写）
  7. 给 D 和 E 一个小测试词库
  8. 管理迁移编号；D、E 的建表语句要编号的话找你登记
验收：真实查词成功；空库和未命中能区分；重复导入不重复；导入失败后旧库能查。

六、D 个人词汇与统计
--------------------
负责：src/vocab/vocab.h  src/vocab/vocab.cpp，自己的数据表
现状：存在内存，重启就丢；统计按 UTC 划日期（要改成 Asia/Shanghai）。
必须保留的公开函数：
  void open(dataDir)  void close()
  ErrorCode recordLookup(id, word, opId)   记一次正式查词；同一个 opId 只记一次
  ErrorCode setFavorite(id, word, value)
  ErrorCode setNote(id, word, text)        超过 5000 字返回 BadRequest，原内容不变
  ErrorCode setPaused(id, word, value)
  Result<VocabPage> list(query, stages)    stages->stageOf(id) 可以读 E 的阶段
  Result<HistoryPage> history(page, size)  最近的在前
  Result<Stats> stats()                    14 天活动；阶段数由 A 从 E 那里填
  ErrorCode addReview(id)                  A 在每次正式提交（非重复）后调用
  bool isPaused(id)                        E 选题时调用
  int pausedCount()
要做：
  1. 收藏、笔记、暂停、查词事件、复习次数写进数据库，重启不丢
  2. 重复收藏只有一份；笔记支持中文、多行、引号
  3. 分页：默认 20 条，最多 100 条；总数和筛选条件一致，排序稳定
  4. 统计：最近 14 个自然日（含今天），没活动的日期补 0，按 Asia/Shanghai 划日期
  5. 只读 E 的阶段，不改复习成绩
验收：重复收藏无副本；笔记重启不丢；建议请求不进历史；分页、暂停、统计正确。

七、E 复习与记忆
----------------
负责：src/review/review.h  src/review/review.cpp，自己的数据表
现状：凡是初始化过、没暂停的词都会进复习，不看到期时间；判分后阶段不变；没有错词重练；数据在内存里。
必须保留的公开函数：
  void open(dataDir)  void close()
  void bind(dict, vocab)                    A 启动时传入，用来读词条和暂停状态
  ErrorCode ensureState(id)                 第一次查到这个词时建学习状态，已有就不动
  int stageOf(id)                           D 列表和统计要用
  void countStages(s0, s1, s2, s3)          统计用
  Result<SessionId> start()                 开始一轮
  Result<NextQuestion> next(sid)            取下一题，没有了返回 has=false
  Result<Hint> hint(qid, level)             level=0 表示取下一级
  Result<Grade> submit(qid, answer)         重复提交返回同一结果，duplicate=true
  Result<Summary> summary(sid)
要做：
  1. 选题：有学习状态、已到期、没暂停（vocab->isPaused）、有释义的词；按到期时间和 ID 排序；每轮最多 12 道正式题
  2. 出题：用释义出题，释义里出现的目标词要遮住；题目里不能带答案
  3. 提示三级：首字母 → 英文释义 → 中文释义；保存最高级别，重复请求不重复累计
  4. 判分：去空白、不分大小写、严格匹配；错了或看答案算没掌握
  5. 阶段 0~3，间隔 1/3/7/14 天：答对没用提示升一级，答对用了提示不变，答错降一级（最低 0）
     第一次接触是阶段 0，1 天后到期；单纯查词不推迟已有的到期时间
  6. 错词重练：正式答错的词本轮再练一次，不改正式成绩，计入 practice_count
  7. 成绩和学习状态在同一个事务里保存，重启不丢
  8. 后期接 A 的 AI 例句（kind=ai），失败就回退到本地题
  9. 时间用 Clock，测试时换假时钟，不要真的等几天
验收：重复提交只记一次；重练不改正式成绩；初始题目不泄露答案；用测试时间验证到期规则。

八、模块之间怎么调用（不要绕开 A 直接改）
----------------------------------------
正式查词：B 提交 → A → C.lookup → 命中后 D.recordLookup + E.ensureState
建议/读词条：B → A → C.suggest / C.get，不记历史
正式复习：B 提交答案 → A → E.submit → 不是重复提交就 D.addReview
统计：B → A → D.stats，阶段数由 A 调 E.countStages 填进去
AI 例句：A 生成，E 决定用不用、失败怎么回退，B 显示来源
