## 1. 目的与背景

本项目以 Lexica 为参考，用 C++ 实现本地英语查词、个人词汇管理和复习业务，再通过网页界面提供完整操作流程。目标用户为希望在阅读、查词和复习之间保留学习记录的英语学习者。

需求文档定义“必须产生什么行为、如何判断完成”；开发计划定义“由谁、何时完成”；详细设计定义“类、数据库和接口如何实现”。本文件不要求逐行翻译 Rust，也不把原项目的开发命令、安装包大小和测试数量作为复现目标。

### 1.1 已确认约束

- 本期以核心复现为主，个人语境、易混词等创新列为后续扩展。
- 团队五人，组长使用 Cursor；其他成员可以使用不同 IDE，但应统一编译器、架构、C++ 标准和依赖版本。
- 课程要求至少 80% C++；统计口径尚未确认，不能单凭业务功能占比或 GitHub 语言比例判定达标。
- 团队主要手写 C++，前端后期集中采用 Vibe Coding；前端生成代码仍须人工审查和真实接口验收。

- 查词、复习判分、调度、AI 请求和持久化逻辑由 C++ 实现。

## 3. 用户场景与主流程

### UC-01 查词和保存

前置：程序已启动，词库就绪。用户输入单词并提交；系统显示词条并记录一次查词；用户收藏并保存笔记。重启后收藏、笔记和历史仍可读取。建议列表变化和空查询不计入正式查词。

### UC-02 完成一轮复习

前置：存在到期且未暂停的学习词。用户开始复习，查看题干，可逐级获取提示并提交答案；系统本地判分、给出反馈、更新正式记录与下次复习时间；错词进入本轮练习队列。结束后区分正式成绩和练习次数。

### UC-03 AI 增强与失败回退

用户主动开启 AI 并配置服务。查词缺少例句时可补充生成；复习需要 AI 填空题时发起请求。缓存有效则复用；网络失败、超时或内容不合格时，明确显示状态，复习使用本地释义题继续。

### UC-04 首次使用和空词库

系统识别词库未就绪并提供导入入口。用户可暂时跳过，但应看到“尚未导入词库”，不能将其显示成普通“未找到单词”。导入失败保留已有词库，展示可操作的错误原因。

## 4. 功能需求与验收条件

### 4.1 词库与查词

**FR-01 启动和状态识别｜P0｜A/B**

- 系统启动时检查数据目录、数据库版本和词库状态。
- 空词库、路径不可写、数据库损坏应区分显示；不得静默删除或重建已有用户数据库。
- 验收：分别使用正常库、空库、不可写目录和损坏测试库启动，记录状态和错误。

**FR-02 手动词库导入｜P1｜C，A 提供接口，B 页面**

- 支持选定本地 ECDICT SQLite 文件，检查必要表和字段后执行导入。
- 界面显示进行中、成功、失败状态；成功报告新增/跳过/失败数，统计口径写入导入说明。
- 同一来源版本重复导入不得产生重复词条。来源更新与覆盖策略另行设计；首版不承诺自动同步更新。
- 导入使用事务或可恢复批次；失败不得导致收藏、笔记和旧词条关联丢失。
- 验收：正常文件、错误格式、重复导入、模拟中途失败；失败后仍可查旧词。
- 自动下载为扩展：用户主动触发；提示来源和下载状态，失败后仍可选择本地文件。

**FR-03 单词查询｜P0｜C**

- 输入去除首尾空白，英文大小写按统一规则处理；空输入不查询、不写学习记录。
- 精确命中优先；返回稳定词条 ID、规范拼写、可用音标和释义。
- 未命中显示明确结果，可附前缀建议；词库未导入应返回不同错误。
- 验收：apple、Apple、前后带空格、空字符串、未知词及含引号词条；输入不能被拼成可执行 SQL。

**FR-04 前缀建议｜P1｜C，A 接口**

- 返回受限数量的前缀候选，建议默认最多 8 条。排序规则固定并记录在接口文档中。
- 过期响应不得覆盖较新输入的结果；输入建议不创建查词记录。
- 验收：多次快速输入、删除为空、无候选；返回数量和当前输入匹配。

**FR-05 词形回退｜P1｜C**

- 精确查询未命中时，按导入的词形映射查原型；返回原查询与实际命中词。
- 映射可能一对多，不得承诺唯一正确的句中词性；多候选可显示供选择。
- 验收：使用人为确认的测试映射，例如 running → run；有精确词条时优先返回精确词条，无映射时正常未命中。

**FR-06 查词历史｜P1｜D**

- 用户实际提交并命中词条才新增一次接触事件；建议请求、复习页面读取和统计查询不写查词事件。
- 历史按最近时间展示。重复查同词保留底层事件，展示是否去重需固定为接口合同。
- 建议首版显示每词最近一次历史，同时统计保留真实查询次数。
- 验收：两次明确查词与多次建议请求后，查词事件为两条，重启后仍可读取。

**FR-07 键盘与导航｜P1；深链接为扩展｜B**

- 候选可用上下键选择、回车提交、Escape 收起；无候选不访问越界索引。
- 词条间导航与浏览器刷新不应引发重复提交。深链接如纳入范围，需支持合法词参数和无效参数提示。
- 验收：只用键盘完成查询；空列表、首尾边界均无错误。

### 4.2 阅读与个人词汇

**FR-08 完整词条｜P0｜C/B**

- 展示词头、已有音标、中英文释义和可用例句；缺失字段隐藏或标为暂无，不伪造数据。
- 词典例句、用户原句和 AI 生成例句分别标注来源；AI 内容不得覆盖词典释义。
- 验收：完整词条、仅中文释义、无音标、无例句都能正常展示。

**FR-09 递进阅读和复制｜扩展｜B/C**

- 如启用循序理解模式，应明确每一步展示内容，并将理解程度变更交给 C++ 记录。
- 复制内容只包含词条实际可见的有效信息；复制失败给予提示。
- 验收：同一词条在两种阅读模式可切换，缺失释义不会出现空白死路。

**FR-10 搭配与语义关系｜扩展｜C/B**

- 仅展示数据源确实提供或经人工核对的搭配、近义词、反义词；无数据不构造关系。
- 点击关联词执行普通查询流程，未收录时提示未找到。
- 验收：有关系、无关系、关联目标未收录三种情况。

**FR-11 收藏和笔记｜P0｜D**

- 同一词只能有一份收藏状态；重复设置“已收藏”结果不变。
- 笔记支持中文、多行和普通标点；建议上限 5,000 字符，超限明确拒绝且保留编辑内容。
- 保存失败不得显示成功，取消收藏不删除历史或复习成绩。
- 验收：保存、修改、取消、重复收藏、超限、引号、多行、关闭重启。

**FR-12 我的词汇列表｜P1｜D**

- “我的词汇”包含已接触或已收藏的词；提供收藏、学习阶段、暂停状态及词头搜索条件。
- 列表默认建议每页 20 条，接口限制最大 100 条；总数与过滤条件一致，排序稳定。
- 这些分页参数为本项目建议，冻结时可调整。
- 验收：空列表、多页、组合筛选、最后一页数据变化，无重复或遗漏。

**FR-13 暂停与恢复复习｜P1｜D/E**

- 暂停词不进入新生成的复习队列；恢复不删除原学习历史。
- 已开始会话内暂停的词，建议在进入下一题时跳过；已提交成绩保留。
- 暂停指应用内复习资格，不默认包含桌面系统通知功能。
- 验收：暂停到期词后新队列无该词；恢复后按到期条件重新选择。

### 4.3 复习与记忆

**FR-14 复习选词和会话｜P0｜E**

- 从具有学习状态、已到期、未暂停且具备有效题干的词中选取；收藏不是唯一入选条件。
- 一轮正式题最多 12 题；错词重练属于额外练习，不计入正式题数量。
- 建议按到期时间、词 ID 稳定排序，选词不重复。没有到期词显示空状态。
- 刷新会话不得生成重复成绩；首版可提示原会话失效并重新开始，不能伪造完成摘要。
- 验收：0、1、12、超过 12 个到期词；暂停词、无题干词均不进入正式题列表。

**FR-15 题目来源与回退｜P0/P1｜E/A**

- AI 关闭或生成失败时仍可进行本地释义题；有效 AI 例句用于填空题。
- C++ 校验后挖空完整目标词，再将题干发给前端；初始题目响应不包含明文标准答案。
- 本地题优先用可用释义；若中英文均缺失则跳过并报告原因。释义中的目标词也需处理，避免直接泄露答案。
- 题干明确是 AI 填空还是本地释义题。默认不把“所有题都由 AI 生成”作为离线前提。
- 验收：AI 开/关、词条无例句、无释义、不合格 AI 例句均有确定行为。

**FR-16 三级提示｜P1｜E**

- 顺序为首字母或掩码、英文释义、中文释义；服务端保存最高提示级别。
- 重复请求同一级提示不重复累计。缺失提示内容显示不可用，仍可继续答题或查看答案。
- 提示对成绩质量的影响必须由后端计算，前端不能自行声明“未用提示”。
- 验收：逐级、重复、乱序请求以及缺失释义。

**FR-17 本地判分与正式记录｜P0｜E**

- 答案去除首尾空白、统一英文大小写后比较。首版建议严格匹配，不默认允许编辑距离容错；若要求与原项目一致，另补容错算法测试。
- 错误或主动查看答案记为未掌握；正确结果同时记录提示使用情况。
- 每个正式题 ID 最多写一次正式结果；重复请求返回同一结果且不重复推进复习时间。
- 成绩记录与记忆状态更新应在一个事务或等效原子操作中完成。
- 验收：大小写、空白、空答案、错误答案、连续双击、重复 HTTP 请求、写入失败。

**FR-18 错词重练与摘要｜P1｜E**

- 正式答错的词排入本轮练习队列；练习答案与提示不再次产生正式复习成绩。
- 建议每个错词本轮最多追加一次练习，仍错则列入待巩固清单；该上限为避免无尽循环的本项目建议，非原 README 明示规则。
- 完成摘要分列正式题数、正式正确数、正确率、练习次数与待巩固词。
- 验收：正式答错后练对，正式正确数保持不变；全错仍可结束本轮。

**FR-19 记忆状态与下次复习｜待 Q08｜E**

- 方案一：按原项目 scheduler 规则移植，并依据同一输入事件验证输出一致；不能只复制阶段名称。
- 方案二：教学简化。建议阶段 0/1/2/3，复习间隔为 1/3/7/14 天；首次接触进入阶段 0，下次为 1 天后；正式答对无提示升一级，答对有提示保持，答错或看答案退一级且不少于 0。
- 简化方案每次正式复习后从完成时间计算下次到期；0=学习中，1=熟悉中，2/3=较稳定。仅查词不延后已存在的到期时间。
- 提示次数仍单独保存；重练不改变阶段。间隔与标签均属建议，须在冻结前二选一。
- 验收：使用可控制时间源测试阶段上下限、到期边界、查词不延后、重练不推进；不要依赖真的等待数天。

### 4.4 AI 与配置

**FR-20 AI 开关和服务配置｜P1｜A**

- 默认关闭；保存启用状态、服务地址、模型以及“密钥已配置”状态。支持用户明确执行连接测试。
- 配置视图和日志不得回传密钥；建议正式 Windows 版使用系统凭据管理器。开发演示可从进程环境变量读取，但须标注与原项目差异。
- 只在用户启用并触发相关功能时请求外部服务；密钥未配置时不发送无效请求。
- 验收：初次启动、开关切换、缺密钥、错误地址、配置保存后重启。

**FR-21 生成请求与响应校验｜P1｜A**

- 请求携带必要单词与释义，不默认发送笔记、整篇文章、历史或身份数据。
- 响应必须关联请求中的词和义项，句子非空且包含完整词边界的目标词；仅子串匹配不合格，例如 art 不应匹配 party。
- 校验只证明格式和目标词满足要求，不宣称已证明句子语义绝对正确；界面标明 AI 生成。
- 验收：有效响应、空文本、错义项、错单词、子串、无效 JSON、超长响应；建议限制响应体大小，具体上限写入设计。

**FR-22 缓存、超时与非阻塞｜P1｜A**

- 缓存键至少包括单词、义项、服务地址、模型、提示词版本；仅缓存校验通过的内容。
- 默认单次请求 15 秒超时，不自动重试；用户可以明确再次发起。相同并发请求建议合并，避免重复调用。
- 等待网络时不持有数据库锁；普通查词和界面操作仍可使用。
- 采用异步任务时，状态包含 pending/running/succeeded/failed；前端按合同查询完成结果。
- 验收：第二次同键命中无网络请求，换模型后不复用旧键；超时后本地题可继续，错误响应不入缓存。

**FR-23 查词补句｜P1｜A/B**

- 词条已有例句时不为同一展示目的自动生成替代句；无例句且 AI 开启时才按设定补充。
- 用户切换单词后，旧请求结果不得覆盖新词条；生成失败不影响释义、收藏与笔记。
- 验收：有/无例句、切换词条、慢响应和失败，展示归属正确。

### 4.5 统计、设置与发音

**FR-24 学习统计｜P1｜D**

- 展示最近 14 个本地自然日，含今天；无活动日期补零，按日期连续排列。
- 查词次数来自正式接触事件；复习次数来自已完成正式题，不含提示、重复提交和错词重练。
- 学习阶段和暂停状态分别统计，避免把“暂停”混当成一种掌握程度。
- 验收：预设跨午夜数据、空日期、重复提交、重练和暂停词，人工复算与页面一致。

**FR-25 偏好设置｜P1；主题动画扩展｜A/B**

- 基线建议包含阅读字号、AI 配置、词库导入入口；字号变化后内容不溢出。
- 主题浅/深/系统模式和循序阅读设置按最终范围启用；圆形主题动画不作为核心可用性前提。
- 非敏感外观偏好可单独保存；学习记录不得只存在浏览器缓存中。
- 验收：修改后重启可恢复，无效配置回退默认值且不影响学习数据。

**FR-26 离线发音｜扩展｜A**

- 检测系统可用的离线英语语音；没有语音时明确提示不可用。
- 不以需要外网的语音服务冒充离线发音，不依赖 ECDICT 提供完整音频。
- 验收：有/无英语语音环境、连续点击和播放失败。

## 5. 数据需求

### DR-01 数据分层

| 类别 | 内容 | 要求 |
|---|---|---|
| 基础词库 | 词条、原始释义、音标、词形、来源版本 | 保留来源；不被 AI 或用户笔记覆盖 |
| 学习数据 | 接触事件、收藏、笔记、暂停、正式复习 | 持久化到本机，重复操作不重复成绩 |
| 派生状态 | 阶段、到期时间、统计 | 从一致的事件与规则得出；规则版本可追踪 |
| AI 数据 | 合格例句、缓存键、任务状态 | 与原始词典分开；不存明文 API Key |
| 用户偏好 | 字号、主题、服务配置 | 外观和业务数据分离，密钥单独管理 |

ECDICT 作为建议基础词源。它的文本释义不保证中英文逐行配对，因此不得简单按行号构造“精确双语义项”。第一版可保留原始释义块，细分义项另行人工核对或明确标注解析结果。不能假设词库自带完整例句、音频或近反义词关系。

### DR-02 一致性与迁移

- 稳定词条 ID 关联收藏、笔记和复习，重新导入不能随意重排后造成错绑。
- 时间存 UTC，界面按明确的本地时区转换；全组使用一致格式。
- 数据库启用所需约束与索引，SQL 使用参数绑定。迁移有版本号和顺序，运行前检测兼容性。
- 迁移或写入失败应显示错误并保留原数据；备份与恢复方式在运行说明中提供。
- 若采用简化算法，记录算法版本；修改算法后明确旧状态如何处理，不静默更换规则。

## 6. 界面和接口约束

### 6.1 页面清单

| 页面 | 必要内容 | 必须表达的状态 |
|---|---|---|
| 查词 | 输入、候选、词条、历史入口 | 未导入、加载、命中、未命中、失败 |
| 我的词汇 | 搜索、列表、收藏、笔记、暂停 | 空列表、保存中、保存成功、失败 |
| 复习 | 题干、提示、答案输入、反馈、摘要 | 无到期词、作答中、已提交、重练、结束 |
| 统计 | 14 天活动与阶段分布 | 无数据、加载、错误 |
| 设置 | 导入、阅读偏好、AI 服务 | 未配置、连接测试中、失败、已保存 |

前端只负责输入、展示和交互状态；评分、复习时间、缓存有效性、正式统计以 C++ 返回值为准。假数据演示必须标记，不可用于最终功能验收。

### 6.2 接口合同

具体 URL 和类名属于详细设计；至少定义以下业务操作：服务状态、导入、查词、建议、历史、个人词汇查询、保存笔记/收藏/暂停、开始复习、取提示、提交、练习检查、摘要、统计、AI 配置、连接测试、生成及任务结果。

每项操作写清输入类型、字段可空性、长度限制、返回结果和错误。单词/义项/题目/任务 ID 不得混用。提交应具备幂等语义；查词若写接触事件，要明确一次用户动作的计数边界，不能因网络重试重复记数。

采用 HTTP 时建议成功为 `{ok:true,data:...}`，失败为 `{ok:false,error:{code,message}}`。参数错误、词库未就绪、未命中、题目失效、数据库错误和 AI 错误应有不同业务错误码。空集合是正常结果，不应统一报错。
