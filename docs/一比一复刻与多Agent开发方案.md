## 3. 已确认的技术路线

### C++ 业务及桌面宿主 + 原版网页界面

用户已确认：C++ 实现后端与桌面壳，保留网页界面技术，优先保证外观 1:1。以下架构和 Agent 分工均按此执行。

```text
Svelte 5 / TypeScript / CSS / 原版字体与图标
                    ↓ Transport.invoke(command, args)
              C++ 命令路由与 DTO 序列化
                    ↓
       Dictionary / Memory / Review / Library / AI
                    ↓
         SQLite + Windows 凭据管理器 + 网络

C++ Win32 + WebView2：窗口、前端资源、消息桥、生命周期
```

前端以原版 Svelte 源码、CSS、字体、SVG 为起点迁移，集中替换 API 传输层和 Tauri 相关调用。后端将 Rust 业务语义移植到 C++。原版也是 WebView 桌面应用，这条路线最利于保持排版与交互一致。

WebView2 官方支持 Win32 C/C++ 宿主：<https://learn.microsoft.com/en-us/microsoft-edge/webview2/>。

建议继续使用 C++17，避免与现有模块无关的语言升级。桌面宿主建议 MSVC x64 + Windows SDK + WebView2 SDK；Phase 0 先验证现有 C++ 库切换 MSVC 的构建结果。现有 UCRT64 构建可作为过渡验证路径，Agent 统一使用冻结后的生产工具链。

生产应用通过 WebView2 JSON 消息桥请求 C++，请求包含 request_id / command / args，响应包含 request_id / result 或 error。异步任务和进度通过事件发送。业务入口统一经过 App；现有 HTTP 适配器可保留用于开发与集成测试，并调用相同业务服务。冻结时明确最终使用的传输路径，避免两套业务实现。

宿主将打包的静态资源映射到固定本地虚拟主机，支持静态路由、字体和资源加载；页面只允许约定来源调用命令桥。外链、目录、剪贴板等平台能力逐项封装。生产包不依赖 Vite/Node/Rust 运行环境。

### 语言与实现边界

前端采用 Svelte、TypeScript、HTML/CSS，优先迁移原版页面、共享组件和资源；后端业务及桌面宿主由 C++ 实现，原版 Rust/Tauri 的运行职责由 C++ 接管。前端资源预先构建并随程序分发。

Qt Widgets 全 C++ 界面重写路线不纳入本次计划。各 Agent 应遵循已经确认的混合架构，不自行更换界面框架或重新设计页面。

旧文档提到课程至少 80% C++，统计口径尚未确认。应单独核实此要求是否仍适用，并分别统计自编业务代码、移植前端和第三方依赖；第三方 SQLite/json 代码不能用于充当自编 C++ 贡献。

## 6. 已发现的源码细节与歧义

以下细节对后续 Agent 强制可见，避免照旧文档或 README 猜规则：

1. 原版 `study_group` 的卡片数量上限是 20；旧到期 `review_group` 的上限是 10。本地目前的 12 题不能直接沿用到这两条流程。仓库学习截图中的组数也不能覆盖当前源码。
2. 浏览 Previous/Next 本身不评分；know/hazy/forgot 会立即记录学习评分，其中 forgot 将词再次放到本组末尾。正式填空和重练是另一套计分流程。
3. 卡片评分映射为 know→Good、hazy→Hard、forgot→Forgotten；正式填空答对后，0/1/2/3 提示分别映射 Excellent/Good/Hard/Poor，答错/放弃为 Forgotten。第三级提示是中文释义，并非本地当前实现的直接给答案。
4. 正式判分：规范化全等；目标长度至少 5 字符时允许编辑距离 ≤1。短词要求精确匹配。遮词须处理多次整词出现和边界。
5. 初始强度 context/english/chinese/unknown 分别为 2/1/0.5/0.25 天；熟悉阈值 4 天，稳定阈值 21 天。全部参数与浮点/毫秒舍入按原调度器移植。
6. 弱查词不能把已安排的复习推迟；记忆状态须可从事实事件重建。仅复制状态标签不满足算法等价。
7. 原版复习本地兜底当前走中文释义优先；查词例句、词典例句和 AI 填空的使用优先级需分别对齐调用链。
8. 原版 `planStyle` 当前可配置并持久化，但已检查的学习组调用只传 wordbook/dailyNewLimit/priority。它参与调度的实际效果尚未发现，Phase 0 应登记为“配置存在、行为待动态核对”，不能自行发明三套算法。
9. 原版学习日配额按 UTC 日界计算，活动图按前端传入时区偏移计算；到期学习词也未明显按选中词书过滤。这些可能是原版缺陷，需复现用例后登记为兼容行为或另行获准修复。
10. 某些词书无相应标签数据时，原版会回退到种子词/有词频词集合。界面标题与严格考试词表并不等价，须如实记录。
11. 学习卡的垃圾桶最终调用 ignored/暂停接口，并未建立独立“已熟知”的记忆事件。按可观察行为验收。
12. API Key 参数 `null` 表示保留、空字符串表示删除、非空字符串表示替换。界面只回读是否存在密钥。
13. ECDICT 缺少例句、CEFR 或扩展内容时，按原版数据组合及派生逻辑展示；同一数据源缺字段不能用编造内容补齐。原版 50 个种子词与测试夹具有更丰富内容，要和完整词库分开验证。

普通行为以原版为参照；确认的安全或数据损坏问题单独修复并记录偏差。不要由各 Agent 分别决定兼容口径。

## 7. 数据、接口和目录约定

### 数据模型

优先采用原版 words/senses/examples/collocations/word_forms、encounters/reviews/review_attempts、memory_states、word_notes/ignored_words、app_settings/ai_example_cache、custom_wordbook_words/word_enrichments 的语义。是否完全复用表名在 Phase 0 冻结。

数据库迁移归总控维护一个连续序列。各 Agent 提交迁移需求或独立候选 SQL，总控分配版本、整合验证。SQLite 构建显式启用并验证 FTS5；本地当前 CMake 未显式启用它。数据库连接和锁顺序统一约定；网络请求在数据库锁/事务外运行，写入结果再进入短事务。

旧 C++ 数据库与原版 schema 不同。新模型先用独立文件，旧库保留。迁移收藏、笔记、历史时按规范化词头匹配并留报告；旧阶段无法无损转成原版事件和强度时，显式标记迁移规则及不确定性。原版数据库兼容性作为独立验收项。

### 接口

- 从原版 `src/lib/api.ts` 与 `src-tauri/src/lib.rs` 的命令注册表生成完整契约清单。
- 覆盖 app_info、初始化/导入、查询/建议/理解层级、最近词、词表/笔记/暂停、统计、记忆重建、词书/学习组/评分、复习/提示/提交/重练、AI 配置/测试/生成/扩展及淡忘词。
- 保留业务枚举、字段含义、nullable、默认值、排序和持久化副作用。传输层统一适配大小写命名。
- 正式提交与重试明确操作标识和幂等边界；同一次动作重发与用户主动再次评分分开处理。
- 接口夹具只用于并行开发。交付验证必须另跑实际 C++ + SQLite，覆盖消息桥或 HTTP 真实传输。

src/app/          业务编排

src/desktop/      Win32/WebView2、资源、平台能力
ui/               迁移后的 Svelte 前端
tests/            C++ 单测、契约、SQLite 集成、等价夹具

旧 web 页面在新界面能完成真实查词闭环后切换。所有根目录构建入口、共享头、统一路由和迁移由一个所有者改动。

## 8. 多 Agent 分工及写入边界

建议设 6 个开发任务，由总控串行整合；审核角色在开发提交后独立执行。任务数量不等于必须同时启动的进程数。

| 任务 | 所有权范围 | 必交结果 | 依赖 |
|---|---|---|---|
| A 基础与总集成 | common/storage、App/API、desktop、CMake/构建和契约 | 冻结 DTO/迁移；命令桥；打包与端到端启动 | 最先建立共同基座，后续持续整合 |
| B 词典与词库 | dict 及对应测试 | 完整词条、规范化/建议、导入、种子、下载数据处理、扩展内容 | A 的模型和存储接口 |
| C 记忆与学习 | memory/review 及对应测试 | 调度等价、词书、学习评分、练习/提示/重练 | A 契约；B/D 提供已约定的查询接口 |
| D 个人词汇与统计 | vocab 及对应测试 | 收藏/笔记/暂停、词表、历史、活动和统计 | A 数据合同；C 的 MemorySummary |
| E 前端完整复刻 | ui、前端及页面测试 | 五页、共享组件、主题/偏好/快捷键/音节/语音；接真实 C++ | A 传输合同；可先用固定夹具 |
| F AI 与凭据 | ai 及对应测试 | 网络、15 秒超时、凭据管理、验证、缓存、批量补充和回退 | A/B 的词与义项模型 |

下载状态的 UI/消息传递由 A/E 负责，下载和解压导入业务由 B 负责；F 只管 AI 网络。C 与 D 通过 MemorySummary/事件接口通信，避免相互 include 具体实现。

前端先由一个 Agent 负责，便于稳定复用原版组件。确需进一步拆分时，先由 E 固定布局、全局 CSS、偏好和共享组件，再将 review 页面/StudyWordCard 分给单独任务；该任务只提交局部文件，对共享样式提出需求。

每个任务的交付必须包含：提交 SHA、修改范围、完成的功能编号、测试命令和结果、已知差异、待总控处理的接口/迁移需求，以及可复现操作。仅有截图或“已完成”描述不视为交付。

### 分支规则

- 每个 Agent 独立 worktree 和 `codex/parity-<模块>` 分支，共同从同一冻结提交开始。
- 测试使用每个 worktree/进程独立的数据库和输出目录。
- A 维护公共类型、迁移、命令注册、构建入口；其他 Agent 提出变更申请，由 A 发布新的合同版本。
- Agent 开发前阅读共同契约及源码映射，开发后自己编译和运行对应测试，再交总控逐个合并。
- 合并后保留功能分支提交记录。总控完成集成验证后再处理下一个提交，便于定位回归。

## 9. 开发波次与里程碑

### Phase 0：固定目标与公共基座

由 A/总控完成基线快照、逐功能源码映射、已确认技术路线落地、生产工具链验证、DTO/错误/命令合同、schema 和迁移规划、最小 C++ 宿主及前端真实查词样例。

出口：每个任务能在同一基线构建；有可调用契约与共享测试样本；新增/兼容行为的处理方式明确。之后再启动大规模并行。

### Phase 1：核心并行

B、C、D 分别开发词典、记忆学习、个人词汇；按资源情况将 F 同时启动或排入下一轮。E 可用契约夹具先迁移页面。A 处理接口/迁移集成，避免把未冻结的中央文件交给多个 Agent 修改。

出口：真实 SQLite 下能够查词→收藏/笔记→学习评分→复习→重启读取；记忆状态可重建，统计与数据库一致。

### Phase 2：完整界面与平台能力联调

E 全部接入实际 C++；F 完成 AI；A/B 完成下载、桌面、数据目录、语音/剪贴板等平台边界和打包。所有设置和功能编号都有实现或明确的原版兼容状态。

出口：生产 exe 能完整操作五个页面，断网可完成离线闭环，AI/导入失败能恢复；正式应用不依赖预览桩。

### Phase 3：独立审核、差异修复与交付

由我按下一节标准审核所有模块和实际程序，形成缺陷清单，修复后重新验证对应流程。交付完整源码、可运行包、构建说明、功能追溯表、截图比较、数据迁移说明和差异清单。

这四个阶段是质量出口，不是固定天数承诺。应在 Phase 0 后按实际可用时间估算排期。

## 10. 我后续的审核与修复标准

### 业务等价

- 相同种子/词库、固定时钟和操作序列分别驱动原版与 C++，比较查询、候选顺序、义项/例句、词书取词、判分、提示和调度结果。
- 调度器先做黄金用例：原版输入/输出固定为夹具，C++ 比较浮点容差及毫秒时间戳。补测同刻事件顺序、理解层级更新、弱访问、优先级清除和投影重建。
- 对新学习卡流程单独测试，现有 Playwright 里仍有旧复习路径夹具；通过原版旧测试也不能替代新版学习组验收。
- 正式提交、重练、重复请求、跨会话操作、暂停恢复及退出重启分别验证，按事实记录核对计数。

### 视觉与交互

- 原版和复刻使用相同字体、数据、浏览器内核版本、系统缩放和视口截图；优先覆盖 1180×820、480px 窄屏，以及 759/760/761px 断点附近。
- 首页、命中/未命中、完整长词条、词汇表/空态、学习卡/练习/摘要、统计和设置逐状态比较。
- 三种风格、浅深色、大字号、侧栏折叠、长文本、缺字段、加载/错误分别覆盖。
- 差异图排除受控的时间、光标和动画区域；剩余布局/字体/间距差异逐项修复。截图阈值在固定环境先校准，再作为验收门槛。
- 实际操作核对键盘、输入法、焦点、返回/深链接、快速输入、连续主题切换、语音取消和未保存草稿。

### 存储、异步和故障

- 使用真实临时 SQLite 测导入重跑、迁移、事务失败、重启、投影重建、特殊 Unicode、词库缺字段和长笔记。
- 查词/保存与大词库导入并发；AI 网络慢/超时/非法响应；程序关闭时后台任务退出及连接释放。
- 凭据保存/保留/删除及 UI 只读状态；日志、响应、配置和数据库不泄漏密钥。
- UI 夹具、真实 C++ 核心、真实传输和 Windows WebView2 人工验收分别记录结果。

### 构建和分发

- 从干净目录按文档构建，验证依赖版本和资源完整性。
- 在非开发环境启动 exe/安装包，测试 WebView2 运行时、DPI、离线语音、中文路径、升级和卸载后个人数据。
- 百万词级性能必须用实际数据测量，报告硬件、数据量、冷热状态和 P95；阈值在基线实测后确定。

缺陷分级：数据丢失/错误计分/无法启动为最高优先；关键行为缺失或原版结果不一致为高优先；视觉和非核心交互差异按影响排序。每项记录复现步骤、原版结果、实际结果、根因、修复提交和回归证据。
