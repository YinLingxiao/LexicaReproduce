## 已修复的问题

| 级别 | 问题及影响 | 修复与验证 |
|---|---|---|
| P1 | 学习重放缓存是进程全局变量；两个数据库使用相同请求 ID 时，第二个可能拿到第一个的结果，漏写接触和评分 | 每个 Application 独立缓存，限制数量和大小；新增双库、评分重试、关闭重开回归 |
| P1 | 网络、解压和导入缺少完整协作取消；关闭程序可能等待漫长请求，AI 还可能把取消吞成缓存部分成功 | 共享异步 WinHTTP 适配器、整次请求截止时间、取消时安全等待回调结束；SQL progress handler、批次和解压轮询；真实本地挂起服务器验证约 200 ms 后取消 |
| P1 | 复习收藏把笔记读取失败当空笔记继续保存，可能清空原内容 | 读取失败停止保存并恢复收藏状态；新增界面回归确认没有发出 save_word_note |
| P1 | 卸载脚本对任意传入目录递归删除，安装缺少文件所有权边界 | 安装清单、目录和链接校验；仅删除已拥有文件及空目录，保留其他文件；中文目录安装/升级/卸载及拒绝非法目标回归 |
| P2 | SSE 连接占用 HTTP 工作线程，订阅到上限可能让普通请求无法执行 | HTTP 线程数调整为 16；同时保持 8 个订阅验证查词仍正常 |
| P2 | 非字符串 command 在入队前抛异常，绕过统一 BAD_REQUEST 响应 | Executor 安全读取命令，非法请求交给 Router 校验；真实 HTTP 回归 |
| P2 | 凭据 TargetName 与公共合同的 service/account 不一致 | 由合同常量生成 LexicaReproduce.parity-v1/ai_api_key，并核对测试；不使用原版凭据 |
| P2 | 种子补全依赖 app_info 的写入副作用和全局路径缓存，同路径重建数据库可能漏补全 | 构造 Application 时补全，移除全局路径缓存；新增不调用 app_info 及同路径重建回归 |
| P2 | 打包只检查文件是否存在，可能把旧程序、旧 UI 发给用户；动态 C++ 运行库还需额外部署 | 每次打包重新构建；静态链接 MSVC 运行库；包内带安装脚本与依赖信息 |
| P2 | UI 的真实服务测试仍把 NOT_IMPLEMENTED 当成功预期；自动下载干扰本地隔离测试 | 改为实际查词/提交/笔记/暂停恢复/统计流程；测试启动禁用自动下载，产品默认不变 |
| P3 | AI 诊断 trace 无界增长；开发服务器缺少事件代理；本地代理影响测试就绪探测 | 限制 trace；增加 /events 代理；测试为 loopback 设置 NO_PROXY |

## 运行和边界

PowerShell 在仓库根目录执行 `tools/package.ps1`，然后启动 `dist/LexicaReproduce/lexica_desktop.exe`。生产包不需要 Node 或 Rust，需要 WebView2 Runtime。正常首次启动会尝试准备完整词库；可从设置中导入 ECDICT SQLite。
