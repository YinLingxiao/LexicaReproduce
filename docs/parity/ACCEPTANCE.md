## 本轮代码

- `ecdict.ok` 或 ECDICT 词数达到门槛时，`app_info.dictionary_ready` 为真，`ensure_dictionary` 跳过下载。
- SQLite busy timeout 从 2 秒改为 5 秒，与原版 `database/mod.rs` 一致。
- 窗口和安装快捷方式使用原版图标。
- 桌面里剪贴板 API 失败时使用已有的宿主写入。

词频来源和等级来源已按用户后续要求追加到 schema 6；这是纠正误导性数据展示的明确兼容差异。

## 联合回归与追加修复

- 生产 UI 构建失败的根因是 HTTP 服务读取 `csp.txt` 后保留了文件句柄。现在读取完成即关闭；HTTP 回归验证服务运行时可重命名替换独立测试目录中的策略文件。
- HTTP 验证脚本改为读取源合同和迁移目录，不再硬编码合同 1.1 / schema 5。
- 完整词库复测复现了 5 秒 busy timeout 下的 SQLite 写锁超时。导入现在在取得首条源数据后才创建写事务，批次同时受到原有条数上限和 200 ms 时间上限约束；提交后为已排队的前台数据库回调让出机会。查词仍实际保存接触记录，没有退化成只读或吞掉写入失败。
- 新增慢速插入回归，证明不到 20,000 行时也会及时提交并允许前台学习写入。
- 完整 ECDICT 复测：新增 3,401,132 条，总计 3,401,187 条，导入期间 1,010 次查词全部命中，最大延迟 382 ms，导入耗时 295,207 ms；重启后词数和 ready 状态一致。日志 `build-parity-msvc/final-acceptance-import-fixed.log`，可用 `node tools/test-import-live.mjs <stardict.db绝对路径> <服务exe路径>` 重复验证。
- 真实 340 万词数据库副本完成 5→6 迁移，词条、释义、接触、复习、作答和记忆状态数量保持一致，笔记哈希一致，`PRAGMA integrity_check` 返回 `ok`。原版应用数据库未写入。
- 最新生产页面测试 3/3、界面夹具 22/22、Svelte 检查 0 错误 0 警告；修复后 MSVC Debug 与 Release 的 CTest 各 10/10 通过。

独立迁移副本与用户库升级前备份位于 `build-parity-msvc/test-output/migration-live`、`test-output/user-backup`，不进入 Git。完整公网下载沿用首次对照证据，本轮使用已有原始 ECDICT SQLite 重做全量导入，没有重复下载。
