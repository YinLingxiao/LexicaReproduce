# 启动与查词页修复 · 2026-10-30

基线：`a74d1cd`。本次处理用户实际遇到的启动白屏、未响应，以及深色查词页的信息层级问题。

后续按用户要求，单词和例句的发音入口统一恢复为原来的小喇叭，不显示文字按钮和音色标签。点击播放、再次点击停止；实际音色放在悬停提示和无障碍描述中，失败通过紧凑的感叹号查看原因。已用完整词库副本验证图标尺寸及真实 HTTP / 原生播放，见 [小喇叭截图](evidence/startup-lookup-fix/speaker-icon.png)。

## 修改

- 桌面数据库初始化移到工作线程；窗口立即进入消息循环，显示“正在打开本地词库”，再显示“正在打开界面”。初始化期间可以关闭窗口，工作线程完成或取消后安全回收。WebView 导航完成后才展示界面。
- 种子元数据补全只更新有差异的字段。过去式和过去分词共享同一词形时，保持原先最终保存的 kind，消除每次启动来回改写的操作。回归验证第二次补全的 sqlite3_total_changes 不增加。
- 查词学习记录改为紧凑状态行；词库入口保留，刷新和到期复习操作收进更多菜单。暂停词优先显示“已暂停复习”，不展示保留在数据库里的旧 next_review_at。
- 发音按钮、音标和实际口音在同一行。美音/英音标识始终表达实际音色；完整音色及口音替代说明按需展开。错误保留明确的“朗读失败”入口和详细原因。
- 词频、Collins、CEFR 收成紧凑指标；来源说明与等级来源放进“词条信息”。估算标签仍直接可见，缺失数据仍按缺失显示，不伪造数值。
- 无例句时直接预览已有释义，不用缺失例句占位框代替词义；中文释义已展示后点击 Understood，记录 chinese 而非 english。完整释义按按钮展开，避免重复呈现同一段文字。
- 暂停操作改为“暂停复习/恢复复习”，记忆状态指示同步显示暂停，消除“已移除/学习中”同时出现的矛盾。
- 弹出说明在窄窗口内自动调整位置，保留键盘访问，并清理监听和动画帧。

协议、合同和数据库版本保持 1 / 1.3.0 / 6。本次没有新增数据库迁移。

## 真实数据验证

使用 SQLite 在线备份，以只读连接从真实库取得一致副本。副本有 **3,401,187 个词条**，位于构建输出目录。截图中的笔记改为演示内容，只修改测试副本。

针对打包后的 Release 程序验证了 `happy`、深色主题、480 窄窗口、暂停状态、真实发音和详情弹层。状态行高 **28 CSS 像素**，词头卡高约 **348 像素**，释义区域从约 **598 像素**开始，首屏可以看到词义。

原生 WebView2 使用同一完整副本，设置试听、单词、例句、刷新后的发音通过真实 playing 事件验证。没有进行人工听音，不能据此认定发音质量已经验收。

启动回归在测试数据库持有写锁时检查窗口消息响应，并测试初始化中关闭窗口。打包版最大消息响应约 **16 ms**，关闭成功。普通小型测试库的后台准备为 **13 ms**。

这些时间属于相应测试环境。现场只观察到主线程累计约 72 秒 CPU 时间后恢复响应，没有抓到当时的调用栈；干净副本启动快，不能据此声称原始大 WAL 状态的冷启动也只需几十毫秒。确定修复的是界面线程的同步初始化阻塞，以及重复元数据写入。
